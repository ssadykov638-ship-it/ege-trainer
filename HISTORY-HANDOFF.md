## Формат объектов заданий

### Один вариант ответа

```js
{
  type: 'single',
  text: 'Текст задания',
  options: ['Ответ 1', 'Ответ 2', 'Ответ 3', 'Ответ 4'],
  correct: 2
}
```

`correct` хранится с нуля. Значение `2` означает третий вариант ответа.

### Несколько вариантов ответа

```js
{
  type: 'multi',
  text: 'Выберите два ответа.',
  options: ['...', '...', '...', '...', '...'],
  correct: [1, 3]
}
```

Индексы также с нуля. Порядок выбора ученика не влияет на проверку.

### Короткий текстовый ответ

```js
{
  type: 'short',
  text: 'Назовите исторического деятеля.',
  correct: ['Наполеон', 'Наполеон Бонапарт', 'Наполеон Первый', 'Наполеон I']
}
```

Добавлять только действительно допустимые варианты написания. Проверка игнорирует регистр, пробелы по краям и различие `е/ё`, но не должна принимать другой исторический ответ.

### Последовательность цифр

```js
{
  type: 'digits',
  text: 'Расположите события в хронологической последовательности.',
  context: ['1) ...', '2) ...', '3) ...', '4) ...'],
  correct: ['1234']
}
```

Используется обычное поле ввода с `inputmode="numeric"`. Экранную цифровую клавиатуру не добавлять. Для задания 6 допустимы два порядка пар, если оба указаны в таблице ответов, например `correct: ['3241', '4132']`.

### Сопоставление

```js
{
  type: 'match',
  text: 'Установите соответствие.',
  left: ['А) ...', 'Б) ...', 'В) ...'],
  right: ['...', '...', '...', '...', '...'],
  correct: [2, 3, 0]
}
```

Значения `correct` хранятся с нуля. Ключ книги `341` превращается в `[2, 3, 0]`.

### Контекст, источник или перечень

Длинные отрывки и пронумерованные события хранить в `context` как массив абзацев. Не вставлять ручные переносы строк внутри отдельных слов и не использовать сырой текст OCR.

### Изображение

```js
{
  type: 'short',
  text: 'Заполните пропуск в схеме.',
  image: './assets/oge-history/v18/schema.png',
  alt: 'Краткое точное описание схемы',
  correct: ['...']
}
```

Вырезать сам материал задания, а не всю страницу. Не обрезать легенды, условные обозначения, номера объектов и подписи, необходимые для ответа. Не включать в картинку текст самого вопроса, если он уже показан в HTML. Для заданий 8–10 использовать один и тот же объект карты и один путь к файлу. Для заданий 13–14 повторно использовать один объект культурных материалов.

### Таблица

Обычная таблица:

```js
table: {
  caption: 'Название таблицы',
  headers: ['Год', 'Показатель 1', 'Показатель 2'],
  rows: [['1900', '10', '20'], ['1910', '15', '30']]
}
```

Таблица с группами столбцов:

```js
table: {
  caption: 'Название таблицы',
  labelHeading: 'Год',
  groups: ['Первая группа', 'Вторая группа'],
  columns: ['Показатель A', 'Показатель Б'],
  rows: [['1900', '1', '2', '3', '4']]
}
```

Все значения, единицы измерения и заголовки переносить полностью. Таблица должна быть нативным HTML, а не скриншотом. На телефоне групповые таблицы автоматически превращаются в читаемые блоки через `appendGroupedTableCards` в `app.js`.

## Правила интерфейса, которые нельзя ломать

- Верхняя кнопка полного сброса прогресса удалена и не должна возвращаться.
- Завершённый вариант показывает результат в виде `Вариант N (балл/всего)`.
- Кнопка `Решить ещё раз` создаёт новую попытку, но сохраняет историю и лучший результат.
- ДЗ после завершения остаётся заблокированным для ученика.
- `Разбор ошибок` показывается после завершения и содержит полное условие, контекст, варианты, таблицу или изображение, ответ ученика и правильный ответ.
- В разборе не показывать строку `Эталон из таблицы ответов`.
- Счётчик `Закрыто` и точность учитывают сохранённые попытки даже во время повторного прохождения.
- Не менять рабочие варианты ЕГЭ, ОГЭ по обществознанию и историю 1–17 при добавлении следующих вариантов.
