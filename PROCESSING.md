# Обработка тренировочных вариантов

## Эталоны и обязательные правила

- Эталоны оформления: «Тестовый вариант» и «Вариант 1». Не заменять их автоматически результатами OCR.
- Каждый публикуемый вариант содержит все 16 заданий первой части в правильном порядке. Неполные исходные варианты пропускать, а не заполнять выдуманными заданиями.
- Видимая нумерация последовательная по фактически добавленным вариантам. Исходный номер сохранять отдельно. Сейчас исходный вариант 3 пропущен: видимые 1 и 2 соответствуют исходным 1 и 2; начиная с видимого 3 исходный номер на единицу больше.
- OCR является черновиком. Исправлять ошибки распознавания по исходным страницам, не менять смысл неверных утверждений в вариантах ответа.
- Разделять задания по началу самого задания, не по слову «Ответ»: OCR может пропустить его и склеить соседние задания.
- Сохранять реальные тексты всех вариантов ответа; цифровые заглушки вместо утверждений недопустимы.
- В заданиях на соответствие сохранять порядок пяти строк и порядок категорий. В данных индексы ответов начинаются с нуля.
- Ключи брать из таблицы ответов исходного сборника; не угадывать по распознанному тексту.

## Задание 9 во всех вариантах

- Условие находится только в текстовом блоке приложения.
- Картинка содержит только диаграмму, шкалу, названия групп и полную легенду. Не дублировать условие или утверждения на картинке.
- Компоновка: диаграмма сверху, легенда снизу, как в эталонах.
- Не срезать проценты, подписи осей, группы респондентов или определения закрашенных частей.
- Границы сканов задаются отдельно для каждой исходной страницы. Автоматический поиск линий на наклонённых сканах недостаточно надёжен.
- Не ограничивать высоту картинки так, чтобы легенда уменьшалась до нечитаемого размера.

## Воспроизводимая сборка

Все команды выполнять из корня проекта. Исходные PDF/страницы и OCR хранятся отдельно и не входят в этот репозиторий. Параметр `SOURCE_ROOT` обозначает каталог с `build_social2026_interactive.py`, `social2026_ocr_variants_v2` и `social2026_variants_raw_v2`.

```powershell
python tools/rebuild_social_variants.py --source-root SOURCE_ROOT
python tools/layout_charts.py --source-root SOURCE_ROOT
python tools/review_charts.py
```

- `rebuild_social_variants.py`: пересборка видимых вариантов 22–29 по границам заданий, ручным исправлениям и исходным ключам.
- `layout_charts.py`: отдельные проверенные границы диаграмм и легенд исходных вариантов 4–30; обновление картинок видимых вариантов 3–29.
- `review_charts.py`: контактные листы для визуальной проверки всех обработанных диаграмм.
- Для Python нужны Pillow; скрипты пересборки используют стандартную библиотеку.
- Результаты проверки находятся в `review/` и исключены из Git.

## Проверка перед публикацией

```powershell
python -m http.server 4173
# В другом терминале, с установленным Playwright и Chrome:
node tools/verify_variants.cjs
node tools/verify_answers.cjs
python tools/verify_answer_keys.py --source-root SOURCE_ROOT
git diff --check
```

Проверка Playwright не выполняет запись в Supabase и блокирует обращения к нему. Она проверяет 298 отображений: задания 9 всех 29 вариантов и все задания вариантов 22–29 на ширинах 390 и 1280 пикселей. Проверяются количество заданий, исходный порядок, отсутствие цифровых заглушек, структура соответствий, загрузка картинок и горизонтальное переполнение. Скриншоты сохраняются в `review/`.

Автоматические проверки не подтверждают смысл OCR или полноту обрезки. До публикации вручную сверить тексты с исходными страницами, все контактные листы и скриншоты, включая варианты 4, 6, 20, 22, 23 и 29. Проверить выбор ответов и переходы между заданиями.

При изменении опубликованных данных/картинок обновлять `APP_VERSION` в `app.js` и версии ресурсов в `index.html`, чтобы браузер не показывал старые файлы.

## Перенос в GitHub

Репозиторий: `https://github.com/ssadykov638-ship-it/ege-trainer.git`.

Переносить данные, картинки, стили, версии ресурсов и инструменты одним согласованным набором. ZIP содержит снимок проекта; Git bundle содержит историю и подготовленный коммит. Перед отправкой сравнить текущую удалённую ветку с локальной; не использовать force-push и не перезаписывать чужие изменения. Исходные материалы нужно перенести отдельно, если дальнейшая обработка будет выполняться на другой машине.

`supabase-config.js` содержит публичный publishable key, не административный ключ. Не добавлять пароли, токены доступа GitHub, service-role ключи или файлы `.env`.
